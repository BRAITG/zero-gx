# Community Server and Levels Repository Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Cloudflare Worker (D1 + R2) and a public GitHub levels repository that accept community level submissions through reviewed pull requests, verify demos, and keep boards and rankings, with Google sign-in behind an interface that works with mocks until the Play Console account exists.

**Architecture:** All server code lives in this repository under `server/` (TypeScript, AGPL). A shared core (`server/src/core/`) ports `LevelFormat.validate` and `DemoCheck` and is used by both the Worker and a CLI that the levels repository's GitHub Action runs. Shared fixtures in `fixtures/` are generated by Godot and checked by both the Godot tests and `vitest`, so the two implementations cannot drift. The Worker talks to GitHub as a GitHub App over plain `fetch`.

**Tech Stack:** TypeScript 5, Cloudflare Workers, D1, R2, Wrangler 4, `vitest` with `@cloudflare/vitest-pool-workers`, Node 22+ for the CLI, GitHub REST API, Godot 4.7.2 for fixtures.

**Spec:** `docs/superpowers/specs/2026-10-16-community-design.md` (sub-project 3; sections "Sign-in", "Submitting and reviewing", "Scores and rankings", "Data").

## Global Constraints

- Every community request needs a session; submissions and score posts also need a fresh Play Integrity verdict. Session tokens are valid for 7 days.
- Submission limits: level JSON ≤ 64 KB, demo ≤ 512 KB (`Demo.MAX_BYTES = 524288`), at most 3 open submissions per player and 5 submissions per player per day; one open submission per level.
- Score posts: at most 30 per player per minute; a player keeps one best score per level hash; a beaten score's demo is deleted from R2.
- A level version is identified by the SHA-256 (64 lowercase hex) of its file's exact bytes. Community files are `levels/<lvl_id>/v<N>.json`, level ids are `lvl_` + 10 characters from `[a-z0-9]`.
- Pull requests may only add files under one `levels/<lvl_id>/` and `proof/<lvl_id>/`; only the bot changes `index.json`.
- The repository never holds a player's name or Google identity; `meta.json` holds an opaque author id.
- Boards return the top 100 plus the requesting player's own row.
- The community player ranking is recomputed every 10 minutes (cron).
- Code comments and docs in normal English; `tests/run.sh` exits 0; `npm test` in `server/` exits 0.

## Rulings that refine the spec

- **R1 Index ownership.** The bot (Worker) writes `index.json` after each merge, because author display names live only in D1; no `index.yml` Action. Moderators hide a level by adding its id to `hidden.txt` (one id per line) through a pull request; the bot leaves hidden levels out of the index and the Worker refuses their scores.
- **R2 Scores are computed by the server.** `POST /scores` sends only the demo. The server takes fuel, hull and clock time from the demo and computes points with the default weights (`BASE_POINTS 1000`, fuel 15, hull 3, time 2 per second, minimum as in `Progress.MIN_POINTS`). The app will only post runs made with default tuning (sub-project 4).
- **R3 Clock rule (parked from sub-project 1).** A demo has exactly one `CLOCK_STARTED` event, at the first frame whose ship has `firing` set, within one frame; seconds are `(frame_count − clock_frame) × STEP`, compared to claims with a two-frame tolerance.
- **R4 Verification is pluggable.** `Verifier` has a Google implementation and a test implementation; the Worker uses the test one only when the `ALLOW_TEST_VERIFIER` variable is `"1"` (never set in production).

## Review Focus

1. **Hostile demos and levels from the network:** oversized, truncated or malformed bodies must yield a 4xx with a sentence, never an exception or a Worker CPU timeout. Test in Task 3 and Task 6.
2. **Replayed or stolen tokens:** a reused nonce, an expired session, a session signed with another key, or an integrity verdict for another package must be refused. Test in Task 5.
3. **Concurrent submissions:** two submissions for the same level at once must not create two open pull requests. Test in Task 7 (D1 unique index on open submissions per level).
4. **Webhook forgery:** a webhook without a valid `X-Hub-Signature-256` must change nothing. Test in Task 7.
5. **Score race:** two score posts from one player for one level must leave only the best score and exactly one stored demo. Test in Task 6.
