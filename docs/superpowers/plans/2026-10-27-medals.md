# Medals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Won stages earn bronze, silver or gold from their best score against a per-stage `par`; official par is authored in the level file, community par rides in the sketch (from the proof run) with a moderator label override.

**Architecture:** `Progress.medal`/`next_threshold` own the fractions. `par` is an optional level-file key carried by `Level.par`; for community stages it comes from the list row (`versions.par`, from the sketch's `par` or a `par:<n>` PR label) and is cached beside the level. `ScoreIcon.Kind.MEDAL` draws the icon; rows and the result card show it.

**Tech Stack:** Godot 4.7.2 GDScript; Cloudflare Worker (TypeScript, D1, vitest); GitHub Actions templates in `levels-repo/`.

**Spec:** `docs/superpowers/specs/2026-10-27-medals-design.md`

## Global Constraints

- Gold ≥ par, silver ≥ ceil(0.7·par), bronze ≥ ceil(0.4·par); below bronze: no medal. No par → no medal, no thresholds. Training has no par.
- `par` is an optional integer top-level level key ≥ `Progress.MIN_POINTS` (100); both validators accept it; `build`/`serialize` round-trip it. Unknown keys stay unrejected.
- Community par never computed on the Worker: sketch `par` (from the proof, by `DemoCheck.score` default weights) or the `par:<n>` label, else NULL.
- The `preview` job's sketch byte comparison stays strict.
- Medal colours: bronze `#c8803c`, silver `#c9d2e3`, gold `#ffcf4a`; icon in `ScoreIcon` flat style, SIZE 30.
- Existing tests stay green: `tests/run.sh`; `cd server && npm test && npm run typecheck`.
- Public text in normal professional English.

## Review Focus

1. Par exactly at a threshold boundary and fractional thresholds (e.g. par 1001 → silver at 701) — Task 1 tests.
2. An official level with `par` below 100 or non-integer is refused by both validators — Task 2 tests (GD + TS).
3. A community row with `par` but no local best, and a local best with `par: null` — Task 7 test.
4. Two `par:` labels or `par:abc` on a submission PR fail `check-pr` with the exact sentence — Task 6 test.
5. The result card on a training stage (no par) shows no medal line and no threshold — Task 4 test.
