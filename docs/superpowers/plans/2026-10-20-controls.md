# Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gamepad, keyboard and mouse control, rebindable bindings, two two-handed touch modes with a side choice, controller-navigable menus, and training rings that work in every scheme.

**Architecture:** Godot `InputMap` actions carry every key, button and stick binding; `Settings` saves and restores them. A new `ShipInput` node, created by `Level`, turns the last-used device's input into the ship's `aim_point`, `steering`, `thrusting` and `align_gate`; a `TouchControls` control draws and reads the two-handed touch modes. Ship physics, demos and the server do not change.

**Tech Stack:** Godot 4.7.2, GDScript, the repository's own test runner (`tests/run.sh`, `TEST_FILTER=<file or file::method>`).

**Spec:** `docs/superpowers/specs/2026-10-20-controls-design.md`

## Global Constraints

- Steering is point to heading: a direction sets `aim_point = ship.global_position + dir.normalized() * 1000.0`.
- Separate fire input fires on press: `align_gate = false`. One-finger touch and mouse click-to-aim keep `align_gate = true`.
- Actions: `steer_left`, `steer_right`, `steer_up`, `steer_down`, `fire`, `pause`.
- Default bindings: keyboard WASD + arrows, Space fires, Esc pauses; mouse left button fires; pad preset A = left stick + A (button 0); preset B = right stick + D-pad up; Start pauses in both presets.
- Stored and captured events use `device = -1` (all devices).
- Settings defaults: `touch_scheme = "finger"`, `fire_side = "right"`, `mouse_aims = true`, `pad_preset = "a"`.
- Virtual stick deadzone: 15% of the stick radius. Ring aim tolerance: 30°.
- Settings persist in `settings.cfg` section `[input]`; a missing or corrupt section keeps defaults.
- Tests never touch the player's real settings (`tests/run_tests.gd` points `Settings.path` at `user://test_settings.cfg`).
- No change to `scenes/demo_recorder.gd`, `scripts/demo*.gd` or `server/`.

## Review Focus

1. **A click or tap on a HUD button must not fire the engine.** `Input.is_action_pressed("fire")` sees clicks that the GUI consumed, so fire is tracked from unhandled events. Test in Task 3.
2. **A pad or key "accept" in a level must not press a HUD button.** Buttons keep focus after a click, and Space or A would then press Restart. In-level HUD buttons use `FOCUS_NONE`; only the result and pause cards take focus. Test in Task 6.
3. **A captured binding must work on every controller.** Captured events carry their own `device` (pad 0, keyboard 16), so capture sets `device = -1`. Test in Task 2.
4. **A touch that starts on a HUD button must not anchor the virtual stick or fire.** Test in Task 4.
5. **A second controller, or a stick resting slightly off centre, must not steal the scheme.** Joypad motion switches the scheme only past 0.5 deflection. Test in Task 3.

### Task 3: ShipInput for pad, keyboard and mouse

**Files:**
- Create: `scenes/ship_input.gd`

**Interfaces:**
- Consumes: Task 1 ship fields; Task 2 actions and `Settings.mouse_aims`, `Settings.touch_scheme`.
- Produces: `class_name ShipInput extends Node`
  - `func _init(ship: Ship)`; `Level` adds it as `var input: ShipInput`, created right after the HUD.
  - `var scheme: String`: one of `"finger"`, `"mouse_click"`, `"mouse_aim"`, `"keys"`, `"pad"`, `"stick"`, `"finger_button"`. It is the last device used. Starts as `Settings.touch_scheme` on touchscreens (`DisplayServer.is_touchscreen_available()`), else `"mouse_aim"` or `"mouse_click"` from `Settings.mouse_aims`.
  - `func steer_direction() -> Vector2`: the world-space steering direction, or `Vector2.ZERO` when not steering.
  - `func fire_held() -> bool`
  - `func touches_rings() -> bool`: true for `"finger"` and `"mouse_click"`.
  - Applies to the ship in `_physics_process` only while `ship.accept_input`; it tracks state either way.
- Rules:
  - Keys and pad: `Input.get_vector(...)` sets the direction.
  - `fire` is tracked from `_unhandled_input` events (`event.is_action_pressed/released("fire")`), never by polling.
  - A key or pad button switches `scheme`, and so does `InputEventJoypadMotion` with `absf(axis_value) > 0.5`.
  - A real mouse (`device != InputEvent.DEVICE_ID_EMULATION`) switches to `"mouse_aim"` or `"mouse_click"`.
  - Emulated mouse events are touches: `"finger"` keeps today's behaviour (moved from `ship.gd`); the other touch schemes ignore them (Task 4).
  - The `pause` action calls `level.hud.toggle_pause()` (Task 6). Until then, guard with `has_method`.
